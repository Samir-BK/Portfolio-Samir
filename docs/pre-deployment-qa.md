## Chat, error, and accessibility details

- **Long answers and resizing** — Chromium streamed a long unbroken fixture at 320 px. The history had 1,301 px of content in a 161 px scroll area. Its client and scroll widths both measured 286 px, and the composer stayed visible. A simulated 568 → 300 → 568 px resize kept the input focused and restored a visible composer in all three engines. Firefox temporarily lost the visible close control in that simulation as described below.
- **Keyboard and labels** — Tab from the chat disclosure reached a suggestion, and Shift+Tab returned to the disclosure with visible focus. The skip link showed a 2 px outline and moved focus to main when activated. The composer has the accessible name “Your question.” The live region uses `role="status"` and `aria-atomic="true"`. Its pending, error, stopped and retry-ready states were inspected. Spoken screen-reader output was not tested.
- **Reduced motion and contrast** — Native Chrome DevTools emulation produced `prefers-reduced-motion: reduce`, automatic scroll behavior, zero transition durations, no hero transform, and a working chat disclosure. The theme contrast unit test passed. Eighteen targeted axe checks across three engines and both themes found no violations on the 320 px homepage, gallery, and blog. These checks do not establish full accessibility conformance. [Chrome DevTools emulation documentation](https://developer.chrome.com/docs/devtools/rendering/emulate-css)
- **Provider and network errors** — A provider failure displayed “The assistant couldn’t answer right now. Try again.”, with immediate Retry. An aborted network connection displayed “Failed to fetch” with Retry. Retrying after the connection recovered streamed a valid Skills source.
- **Input limits** — Whitespace-only input kept Send disabled and created zero turns. Native keyboard input stopped at 600 characters and remained valid. The direct API integration test rejected 601 characters with HTTP 400 and rejected oversized request bodies with HTTP 413. The automation paste helper bypassed the native edit constraint, so this pass does not claim verification of physical clipboard paste.

### Regression coverage

- **Browsers and sizing** — Chromium 157.0.0.0, Firefox 157.0.1, and Safari 26.6.2 (WebKit 605.1.15). Delayed loading covered 320 × 568 and 1280 × 900 in Chromium and Firefox, with a targeted Safari test at 320 × 568. Chat interactions were exercised at 320 × 568 and 390 × 844 in Chromium. The resize comparison used 320 px in Dark. The delayed cases and interaction checks included Light and Dark.
- **Chat behavior** — Suggested questions still returned a Skills source. Shift+Enter inserted a line break and Enter sent. Long unbroken text wrapped without widening the page. At 320 px, the 161 px history region held 1,301 px of content while the composer stayed in view. The network, Stop, cooldown and long-answer scenarios used loopback fixtures and the deterministic fake provider.
- **Automated tests** — `tests/chat-controls.test.mjs` adds coverage for a transport failure followed by successful retry, a dropped response stream, and distinguishing Stop from a connection failure. Lint, TypeScript, 12 unit tests, 6 PostgreSQL checks, 9 chat checks, Prettier and the Turbopack production build passed.
- **Remaining limitations** — The 300 px frame was a viewport simulation. Hardware safe-area insets, physical mobile keyboard IME and dismissal behavior, and spoken screen-reader announcements remain unverified. UI-VIS-01 and UI-PERF-01 remain deferred.
